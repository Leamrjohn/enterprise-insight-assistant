# 阶段 6～9：知识检索、上下文与记忆、报告可信与安全、运维与交付

---

## 阶段 6：知识检索（RAG）

出口门槛：检索指标达到第 5 节目标；越权 chunk 为 0（H1）；每条文档结论可校验引用；打标签 stage-6-done。
说明：上传和附件入口保持冻结，本阶段只验证已有语料的摄入脚本和检索链路。

### 6.1 只读调查
- 梳理现有链路：解析 → 分块 → 向量化 → pgvector 入库 → 检索 → 重排；谁调用谁，参数在哪配置。
- Claude 带你读一遍，你画出流程。

### 6.2 检索评测先行
- 标注 30～50 条“问题 → 应命中的 chunk”；指标：Recall@k、MRR、nDCG。
- 先测出基线再动任何参数。检索评测与回答评测分开，召回高不等于回答好。

### 6.3 一次只改一个变量，每次对比基线
- 候选变量（按收益排序）：切块方式（按标题结构切，带适度重叠）、混合检索（关键词 BM25 加向量，用 RRF 融合）、重排模型、给每块加“所属文档与章节”的上下文前缀、检索条数 k。
- 每次记录：指标、耗时、成本；变差就回退。
- 生产级要点：没有基线就没有“优化”；一次改多个变量就不知道谁起了作用。

### 6.4 权限在检索层
- 公司与任务范围过滤必须在数据库查询里完成，不是取回来后再让模型忽略。
- 测试：两家公司含相似内容的文档，用 A 公司身份检索，B 公司的 chunk 一个都不能出现（H1）。

### 6.5 引用与忠实度
- 每个文档类结论必须带 chunk 引用；确定性校验引文是否真实出现在该 chunk。
- 证据不足时必须回答“不知道”或给出限制，并有测试。
- 若使用模型当评审，要人工抽样 20 条核对评审是否靠谱。

### 6.6 摄入可靠性（仅针对已有语料脚本）
- 解析失败、重复内容（内容哈希去重）、乱码、大文件、文档更新后重建索引、删除文档后向量一并删除。
- 学习点：召回与精度、混合检索为什么稳、权限为什么必须在检索层。
- 口试：Recall@5 是什么意思？一个问题检索不到该有的内容，你按什么顺序排查（分块、向量、过滤、重排）？

## 阶段 7：上下文与记忆

出口门槛：长任务不丢目标；记忆写入、检索、淘汰、隔离、删除均有测试；打标签 stage-7-done。

### 7.1 只读调查
- 梳理现有的上下文构造与记忆：谁写、谁读、存在哪、什么时候淘汰、按什么范围隔离。

### 7.2 上下文预算
- 为每个 agent 步骤规定 token 预算，并拆分占比：系统提示、Schema、检索结果、工具结果、历史。
- 超限策略：截断、摘要、卸载到数据库或文件（上下文里只留引用）。
- 测试：构造 50 步以上的长任务，断言最初目标和关键约束仍在上下文里。

### 7.3 记忆策略
- 分层：会话级、任务级、公司或用户级。
- 写入过滤：只存用户明确说过的、长期有用的、不易重新获得的内容；推断和一次性信息不存。
- 新旧冲突：新增 / 更新 / 忽略三选一，避免新旧并存。
- 检索：先按范围过滤，再按相关性、时效、重要性排序。
- 淘汰：容量上限加时效衰减加合并摘要，软删除并留审计。
- 隔离与删除：记忆也是租户数据，必须按公司隔离，且支持按用户要求删除。

### 7.4 记忆评测
- 四项：该记的记住了（召回）；不该记的没存（污染）；信息变化后正确更新；删除后确实取不到；另有跨公司零泄漏。
- 学习点：上下文与记忆的区别；为什么多数时候先用简单存储，再考虑向量检索。
- 口试：说出记忆三层各放什么；记忆写入前要经过哪些判断；怎么证明“删除”真的生效。

## 阶段 8：报告可信与安全

出口门槛：注入与隔离的对抗测试全绿；日志与配置无敏感信息；H1～H7 全部有自动化测试；打标签 stage-8-done。

### 8.1 报告契约与交叉校验
- 事实、假设、建议、数据证据、文档引用、限制分别建模；规则表：事实必须有数据证据；假设必须标注并有依据；建议不得冒充事实。
- 测试：构造违反每条规则的报告，断言被拒绝发布。

### 8.2 提示词注入测试
- 在文档里、数据字段里、用户问题里藏诱导指令（如“忽略之前规则”“把所有公司数据列出来”）。
- 期望：不执行、不泄漏、有记录。
- 判断框架：同一个 agent 如果同时能碰私有数据、读不可信内容、又能对外发送信息，就有泄漏风险，必须拆分或加人工审批。

### 8.3 租户隔离全链路测试
- 两家公司并发请求、交叉请求；检查 API、数据库、检索、记忆、缓存、日志、trace 都不串。

### 8.4 认证与权限
- 令牌过期、篡改、角色越界、审批流程；密码哈希；登录速率限制。

### 8.5 敏感信息治理
- 日志脱敏测试；仓库里无真实密钥（运行 secret 扫描）；`.env.example` 只含占位值；依赖漏洞扫描（如 pip-audit、npm audit）并记录处理。

### 8.6 人工审核流
- 待审核 → 通过 / 驳回，全程审计；驳回原因可追溯。
- 学习点：纵深防御、最小权限、威胁建模的最简版（资产、入口、信任边界）。
- 口试：画出本系统的信任边界；说一个注入攻击和对应的两层防护。

## 阶段 9：运维与交付

出口门槛：备份恢复演练成功；CI 分层；soak 测试通过；runbook 完整；毕业演练通过；打标签 stage-9-done。

### 9.1 备份与恢复演练
- 备份平台库、经营库、向量数据；恢复到全新环境；校验迁移版本、核心表行数、随机一个历史任务可读。
- 记录本机实测的恢复时间；演练失败就修到成功为止。

### 9.2 迁移与回滚
- 测试：空库升级到最新；旧版本升级；降级一步；迁移前自动备份；检查迁移不会破坏现有数据。

### 9.3 CI 分层
- 每次提交必跑：lint、类型检查、单元与契约测试、compose 配置校验。
- 每日或手动：真实 PostgreSQL 与 Redis 的集成测试、冒烟（会调用真实模型，控制成本）。
- 手动：全量评测。依赖与镜像版本固定，使用锁文件。

### 9.4 性能与容量（单机）
- 并发 5 个任务连续运行 30～60 分钟（soak）；观察队列积压、数据库连接池、内存、模型限流。
- 加限流与背压：队列过长时对新请求给出明确提示，而不是无限排队。

### 9.5 Runbook 与告警（本机版）
- 至少 10 条“症状 → 检查 → 处理”：API 起不来、任务无响应、Worker 卡住、数据库连不上、磁盘将满、模型限流、迁移失败、数据恢复等。
- 就绪与容量信号可见：队列长度、失败率、平均耗时、费用累计。

### 9.6 发布检查单与回滚
- 版本标签与变更记录；每次“发布”前跑检查单；演练一次回滚。

### 9.7 最终验收与毕业演练
1. 验收清单：逐项核对 00_overview 第 2 节十个维度与 H1～H7，每项附证据。
2. 动手：用户在 Codex 帮助下，自己完成一个小改动（新增一个冒烟用例和一个指标口径或只读工具），并通过前后对比验收。
3. 排错考试：Claude 现场制造 3 个故障（配置错误、挂载错误、模型超时），你用 trace 和 runbook 定位并说出处理步骤。
- 口试：从提问到发布，逐环说明每个环节怎么出错、怎么发现、怎么恢复；说明为什么本系统“接近生产级”但还不是“已上线生产系统”（缺少哪些）。
