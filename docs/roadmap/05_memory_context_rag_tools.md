## P0 评测基线

1. 统计每个 Agent 的 token 用量，找出上下文浪费。
2. 重复运行 SQL 结果评测，得到通过率波动范围；SQL 标准答案等用户审核。
3. 检索题扩到 60 题以上，标注到片段，加入新旧文档陷阱题。
4. 新增记忆评测和工具选择评测题目。

验收：每个模块都有可重复的基线数字。

## P1 RAG

1. 文档元数据：版本组、版本号、生效和失效日期、被谁替代、文档类型、适用范围。新版本上线时旧版本标记为已替代。
2. 在 SQL 查询里排除失效文档；问历史时期时按当时有效的版本查。
3. 关键词召回 + RRF 合并；修复多策略合并丢失排序加权的问题；一次只改一个变量；重新验证重排是否值得保留。
4. 片段支持检查：模型逐条判断片段是否支持该句、是否适用；代码核对引用范围、有效期和适用范围；不支持则删句或说明证据不足。

验收：旧片段引用率为 0；Hit@3、Recall@3 高于基线；有引用支持率指标和达标线。

## P2 上下文

1. 每个 Agent 用清单声明需要的输入，没声明的进不去。
2. 每个 Agent 有独立预算，按“规则 > 当前问题 > 约束 > 证据 > 历史”的优先级填入，并记录舍弃原因。
3. 用量到 80% 时精简（比例按 P0 数据调整）：先用代码去重和删字段，不够再用模型摘要；摘要标明来源，约束不能被压缩掉。
4. 当前问题和约束放在提示词末尾，不变的规则放最前面。

验收：每题 token 下降 30% 以上（按基线再确认）；SQL 和路由正确率不下降；长对话中最初的约束仍然有效。

## P3 记忆

1. 分层：会话、事实、偏好、经验。
2. 元数据：层级、适用范围、来源和证据、可信度、重要性、业务有效期、保留期限、状态、最后使用时间、使用次数、嵌入向量。
3. 检索：先用代码硬过滤范围、状态和有效期，再按“相关性 × 时效 × 重要性”排序，受 token 预算限制。
4. 写入：只接收已验证的来源；冲突时新增、更新或忽略，并留审计。
5. 汰换：标记可疑 → 暂停使用 → 人工审核 → 替换、撤销或恢复。
6. 清理：每天把过期记忆转为软删除，保留 90 天后物理删除，全程审计。

验收：该取到的能取到；更新后取到新值；撤销后取不到；跨公司泄漏为 0；被标记的记忆审核前不进入提示词。

## P4 模型调用工具

1. 工具清单：做什么、何时用、何时不用、参数示例、常见错误，版本管理；给模型简介和 JSON Schema，不给全部数据。
2. 按需提供数据：先给表名和说明、已登记指标；需要时用 `describe_table` 取选中表的字段和取值。
3. 精简工具结果：列名、前几行、总行数、统计摘要、是否截断；完整结果留在服务端，用证据编号引用。
4. 错误处理：参数或 SQL 错误返回原因（最多 2 次）；暂时性错误由代码退避重试；权限问题立即停止；重复同样错误判定无进展。
5. 兜底：切换同类工具、降级、熔断（含试探恢复）；最后返回已有结果并标 `partial`；次数、费用、时长都有上限。
6. 上线：影子模式 → 灰度开关 → 数据证明不比固定路线差且用户同意后切换。

验收：工具选择准确率和参数一次通过率不低于固定路线；错误数字和越权调用为 0；故障演练中熔断和切换真实触发。
