## 重要的未完成事项

1. **SQL 标准答案还没经过你审核。** 比如“毛利只算已交付订单”这个口径是我定的。
2. **通过率没有做多次统计。** 模型每次回答不同，22/24 只是一次录制的结果。
3. **有些问题仍然答不了。** “未回款余额”和“无订单客户数”没有登记为指标，你已决定暂不开放（决策 D26）。
4. **演示数据测不出部分错误。** 订单全是“已交付”，所以漏写状态条件的 SQL 结果也是对的。
5. **`COALESCE` 拦截未经完整任务验证。** 只有单元测试和组件评测覆盖。
6. **执行层测试依赖环境变量。** 没设置 `ACME_DEMO_DATABASE_PASSWORD` 时会跳过，以后的 CI（自动化测试流程）必须提供它。
7. **其他待办：**
   - 预算用完且没有报告时，任务仍标为 `partial`
   - uvicorn 访问日志不是 JSON 格式
   - API 发消息请求偏慢（p90 约 1.35 秒，即 90% 的请求不超过这个时间）
   - 阶段 2 还没做出口验收和打标签
   - 4.5 模型选工具的影子实验还没做
   - 阶段 5～9 的其余内容还没做

## 我犯过的错误

这些也值得学习，文档里没有隐藏：

| 错误 | 怎么发现的 | 教训 |
|---|---|---|
| 说模板查询“用超级用户连接” | 动手前看到默认账号不一致，再查真实路径才发现说错了 | 要从被测路径本身取证 |
| 第一次 AST 探测用了不存在的表 | 所有攻击都被拦，结果好得不正常 | 要确认是被目标规则拦下的 |
| 第一次修 3.6 没修到根上 | 复测发现任务仍然“不重试就失败” | 修复必须靠复测验收 |
| 报告校验评测首次显示 100% 拦截 | 发现有的样例是因缺字段被拦 | 要核对拦截原因 |
| 提示词示例写了真实表名 | 已有测试失败 | 该改的是我的代码，不是测试 |
| 把“80 条指纹”当成 80 个真实答案 | 写 SQL 评测时统计才发现 | 调查时要看内容，不能只数数量 |
| 第一次把无答案题集“看分数前提交” | 提交被格式检查拦下，我没看输出，事后才发现 | 提交后要确认真的成功了 |
| 平均分门槛之前一直没暴露问题 | 过滤旧版本后才误拒答 | 修好一层，可能暴露下一层，端到端评测才看得出来 |
| 拿 P0 的 47/48 当路由基线 | 对照实验里旧提示词也只有 43/48 | 单次抽样不能当基线，改动前后要同期跑 |
| 第一版选表以为“表少了不影响” | SQL 掉到 18～20/24，查出缺日期规则 | 删内容可能暴露原来靠巧合才对的地方 |
