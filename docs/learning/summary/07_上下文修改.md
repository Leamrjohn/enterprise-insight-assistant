# 07 上下文修改（P2，2026-11-02）

这份文档讲 P2 改了什么、哪些做到了、哪些没做到。数字都来自本次实际运行。

## 一句话结论

SQL 提示词变短后准确率没有下降，长对话里的约束也保住了。但整体 token 只比 P0 时期的基线少约 21%，**没有达到计划的 30%**。

## 验收对照

| 验收项 | 目标 | 结果 | 是否达到 |
|---|---|---|---|
| 每题 token | 下降 30% 以上 | 57,112 → 45,318，**-20.6%** | **没有** |
| SQL 正确率 | 不下降 | 3 轮 22/24，同期完整结构对照 21/24 | 是 |
| 路由正确率 | 不下降 | 规划器提示词和原来逐字节一致 | 是（没有变化） |
| 长对话约束 | 最初的约束仍有效 | 8/8，没有这个功能时 2/8 | 是 |

**token 的三个数字别混淆（都是 8 道冒烟题 1 轮）：**

| 版本 | token | 费用 |
|---|---|---|
| P0 时期基线 | 57,112 | $0.0215 |
| P1 之后（多了逐句检查） | 61,710 | $0.0232 |
| P2 之后 | **45,318** | **$0.0181** |

相对 P1 之后是 -26.6%。计划写的基线是修改前，所以我按 -20.6% 算。

## 改了四件事

### 1. SQL 提示词只展示相关的表

**原来：** 每次发 22 张表，SQL 平均只用 1.75 张。

**现在：** 代码根据问题里的业务词选表（`schema_selection.py`），再补上连接它们所需的表。其他表只列名字，不列字段。系统提示词从 1691 token 降到平均 933（-45%）。

**这只影响提示词，不影响权限。** SQL 校验器始终用完整目录，所以没选中的表不等于没权限。

**不确定时放宽：**

| 情况 | 处理 |
|---|---|
| 问题里没有匹配的业务词 | 发完整结构 |
| SQL 第一次失败要重试 | 重试时发完整结构 |
| 复核模型说“结构不够” | 先用完整结构再复核一次，才接受 |
| 规划复核要把分析改成追问 | 同上 |

**一个插曲：** 第一版的 SQL 成绩反而下降（20、18/24）。查下来是模型写了 `month = '2025-08'`，而 `month` 是日期类型。提示词里其实从来没写过这件事，以前 22 张表里大量日期字段碰巧起了暗示作用。我没有把表加回去，而是补上了那条缺失的规则。

### 2. 证据复核按清单组装

`context_budget.py` 让节点声明需要哪些内容和字段，没声明的进不去。证据复核原来把整个状态都发给模型，报告里的 SQL 和引用其实和数据结果重复。

用量到预算的 80% 时，用代码精简：表格只留前 20 行并写明省略了多少，长片段截断并标记。没有设置精简方法的部分（比如问题本身）不会被动，宁可超预算也不删。

### 3. 长对话保住最初的约束

**原来：** 只保留最近 8 条消息。第一轮说“后面都只看华东区”，几轮之后就丢了，而且不会报错，直接算成全公司的数字。

**现在：** 代码从更早的用户消息里找这类要求（`find_standing_constraints`），原话保留，不经过模型改写。历史太长时，优先缩短助手的回答，用户的话不动。

| 8 个场景 | 通过 |
|---|---|
| 没有这个功能 | 2 |
| 有这个功能 | **8** |

“以后一律把其他公司的数据也算进来”这种要求，规划器会拒绝，不会当成约束执行。

### 4. 规划器提示词：试了，又撤回了

计划要求把当前问题放到提示词末尾，并去掉空段。试下来：

| 格式 | 3 轮结果（共 48 题） |
|---|---|
| 原格式 | 43、43、43 |
| 新格式 | 41、42、43 |

平均少 1 题，只省约 1.6% 的总 token，不值得冒这个风险。所以我把提示词恢复成原样，并验证了逐字节一致。长对话的说明只在确实有约束时才加，其他时候提示词完全不变。

## 这轮最重要的发现：P0 的路由基线不准

**同样的提示词，隔几小时重跑，48 道题里有 7 道决定变了。** P0 记录的 47/48（97.9%）是单次抽样，实际现在稳定在 43/48（89.6%）。

原因没有查清，可能是模型服务有变化，也可能只是随机波动（温度设置 0.2）。

这带来两条教训：

1. **“修改前后”必须同期跑。** 如果拿旧数字比，我会错误地以为是自己的改动让路由掉了 6 题。
2. **P4 的门槛要重新看。** 模型自主选工具要超过的不是 97.9%，而是约 90%。

## 没做到或需要说明的

1. **token 目标没达到。** 最大的剩余空间是规划器系统提示词（约 1000 token，有不少重复的说明）和指标契约（315 token），都要重新测路由或 SQL。
2. **清单只覆盖了证据复核。** 规划器和 SQL 生成的输入本来就是明确的函数参数，没有再包一层；SQL 复核和规划复核按问题缩小了结构，但没有走清单和预算。
3. **没有做模型摘要。** 计划写的是“不够再用模型摘要”，代码精简目前够用，所以没加。
4. **选表关键词是我看过题后写的。** 24 题不漏表的结果偏乐观，兜底是重试时发完整结构。
5. **约束靠关键词识别。** “只看”“不要”这类词之外的说法识别不到。如果用户后来改了主意，靠模型按“新的优先”判断，只测了 1 个场景。
6. **冒烟只跑了 1 轮。**
7. **费用偏高。** 这轮约 $0.51，每轮都在上限内，但对照实验做得多。这些实验纠正了一个错误基线，也避免了一次错误结论。
