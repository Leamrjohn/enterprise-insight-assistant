# 企业级 Agent 开发教学计划

**目标：** 由我带着你改进本项目，让你最终能**独立开发企业级 Agent 项目**。

**学习方式：** 不单独上课。每个能力都通过真实工单训练，学完要用没见过的新场景验证。

**对应设计：** [企业级总计划](../design/enterprise_plan_2026-11-05.md) 和 [实现设计](../design/enterprise/)。

---

## 1. 先说清楚的三件事

**1. 只读说明，学不会独立开发。** `AGENTS.md` 现在写的是“用户不写代码”。这对验收够用，但你的新目标是独立开发，所以这条必须逐步改变：你要从判断，走到补关键代码，最后自己实现。详见第 3 节。

**2. 你的编程能力还没有测过。** 之前 10 题测的是系统理解，不是动手能力。第 0 阶段要用一次小任务测出来，它决定进度快慢。

**3. 我不保证固定工期，也不保证结果。** 这里用“过关证据”推进，不用时间推进。你的投入时间和编程基础决定速度。团队沟通能力只靠我模拟不够，要尽量找真人验证。

## 2. 起点和目标

等级：0 说不清；1 知道是什么；2 能讲为什么；3 能预测后果和排查；4 能比较取舍并解释代价。

**每项能力目标都是 4 级，且要能在没见过的场景下做到。**

| 能力 | 起点依据（10 题摸底） | 起点 | 最大缺口 |
|---|---|---|---|
| A 需求分析与技术判断 | 校验 2、Planner 1、SQL 1 | 1 | 混淆模型判断和代码强制 |
| B 模型调用与执行机制 | 工具 3、费用 1、恢复 3 | 2 | 预占、未知费用、结构化输出修复 |
| C RAG 与数据处理 | 检索 2 | 2 | 没考虑代价；不会分层定位 |
| D 上下文与记忆 | 记忆 2，上下文未单独测 | 2 | 把记忆当佐证；来源权限 |
| E 评测与实验分析 | 冒烟 0 | **0** | 最低，也最优先 |
| F 可靠性与安全边界 | 恢复 3、SQL 1 | 恢复 3 / 安全 1 | 安全防线分不清 |
| G 交付与团队沟通 | 未测 | 未知 | 第 0 阶段测 |
| H 独立实现（新增） | 未测 | 未知 | 第 0 阶段测 |

**H 是我加的，** 因为没有它，前 7 项只是“能评审”，不是“能开发”。

## 3. 放手阶梯

同一项能力，你逐步接手更多。过关才往下走，不够就停在当前层。

| 层 | 我做 | 你做 | 适合 |
|---|---|---|---|
| **看懂** | 实现并解释 | 开工前预测；验收时先判断 | 第一次接触 |
| **补全** | 给骨架、测试和失败现象 | 写关键的 5～30 行 | 概念已懂 |
| **主导** | 只评审，不替你写 | 设计、实现、测试 | 已能预测后果 |
| **独立** | 事后抽查，不提示 | 从需求到交付全部 | 毕业前 |

**你写的优先是测试和判定逻辑，** 比如一条断言、一个规则、一张表驱动用例。它们代码短，风险低，却最能训练判断。

**用到才学。** Python、SQL、Git、测试框架都在工单需要时学，不先学语法教程。

## 4. 每个工单怎么进行

**这是全部流程，不再额外加步骤。**

| 步 | 谁 | 做什么 | 上限 |
|---|---|---|---|
| 1 预测 | 你 | 不看代码，写：这个问题在哪、改哪里、可能破坏什么 | 3 行 |
| 2 实现 | 按阶梯 | 我做或你做 | 一个工单一个主题 |
| 3 验收 | 你先说 | 看改前改后证据，判断接受或拒绝及理由，我再说我的判断 | 5 行 |
| 4 变式题 | 你 | 一道**相同原理、不同场景**的题，不看资料 | 1 题 |
| 5 记录 | 我 | 更新第 11 节进度表 | 1 行 |

**验收顺序不能反：** 我先说结论，你就只是在附和，学不到判断。

**提示规则：**
1. 你卡住时，我先问一个问题，不直接给答案。
2. 再卡住时，指出看哪个文件或哪条证据。
3. 还卡住才讲解，这一项记为“有提示”。

## 5. 砍掉什么，为什么

| 不再做 | 理由 | 替代 |
|---|---|---|
| 通读 `docs/`、设计文档、学习笔记 | 看完不等于会 | 工单需要哪段读哪段；现有 `docs/learning/` 只当查阅资料 |
| 脱离工单的长篇讲解 | 记不住 | 讲解不超过 10 行，紧跟实际问题 |
| 成批出题 | 容易变成背答案 | 每工单 1 道变式题；阶段末才考 |
| 重复讲已过关内容 | 浪费时间 | 只隔段时间抽查 |
| 让你复述我刚说过的话 | 只测短期记忆 | 换场景提问 |
| 继续打磨计划文档 | 计划已够开工 | 工单里发现问题再改 |
| 重复付费运行“求安心” | 费钱，且小样本说明不了问题 | 先算需要多少样本；优先回放和假模型 |
| 为教学单独造假练习项目 | 脱离真实约束 | 用真实工单，只有毕业项目是新的 |
| 为了好看的分数放水 | 没有用 | 等级只看不看资料时的表现 |

**学习时间的分配原则：** 一半以上花在判断和动手上，而不是听讲。

## 6. 七项能力怎么训练

每项都写清楚：必须做到什么、用哪些真实工单、最后怎么考。

### A. 需求分析与技术判断

**必须做到：** 拿到一个需求，能拆成步骤，判断每步用模型还是代码，并说清准确率、费用、延迟、维护和失败后果。

**判断框架（你要能自己用出来）：**

| 问题 | 倾向代码 | 倾向模型 |
|---|---|---|
| 规则能否写清楚？ | 能 | 难穷尽（语义、改写） |
| 错了后果多严重？ | 涉及权限、资金、发布 | 可被后续校验拦住 |
| 需要稳定复现？ | 需要 | 可容忍波动 |
| 输入是否自由文本？ | 结构化 | 自然语言 |
| 成本和延迟 | 高频、要快 | 低频、价值高 |

**常用组合：模型提议，代码校验，失败有兜底。**

**真实工单：** B2c～B2e（规划规则）、B4d（指标编译）、B5（选句子而不是抄句子）、B2g（语义复核要不要留）。

**考核：** 给一个新需求（如“合同到期预警助手”），你写一页技术方案：步骤拆分、每步选择及代价、需求里不清楚而必须问的问题。

### B. 模型调用与 Agent 执行机制

**必须做到：** 能分别处理超时、错误输出、重复调用、预算耗尽和恢复，并讲清每种情况的费用去向。

| 情况 | 你要能回答 |
|---|---|
| 超时 | 重试几次？费用算不算？调用方还要重试吗？ |
| 错误输出 | 格式错和内容错怎么区分？修复几次？ |
| 重复调用 | 同一任务重复投递时为什么不重复写入？模型费用呢？ |
| 预算耗尽 | 已有证据怎么处理？终态是什么？ |
| 恢复 | 节点执行一半崩溃，哪些会重做？ |

**真实工单：** G1、G2、G4（用假供应商注入每类错误）、T2～T5、T8。

**考核：** 我给一个无注释的假供应商脚本（超时、429、截断交替出现），你先写出预期的账本记录和预算变化，再运行对照，解释差异。

### C. RAG 与数据处理

**必须做到：** 回答错了，能按层定位，每层都有独立验证手段，不靠猜。

| 层 | 问题 | 怎么验证 | 能修什么 |
|---|---|---|---|
| 1 入库 | 文档进来了吗？切对了吗？ | 查 `document_chunks`；看片段是否含答案 | 解析、切分 |
| 2 召回 | 答案在候选里吗？ | 看每步候选（B6b） | 关键词、向量、实体 |
| 3 重排和过滤 | 被排掉了吗？ | 看分数和阈值 | 重排、有效期 |
| 4 进提示词 | 被截断了吗？ | 上下文清单 | 预算、压缩 |
| 5 模型回答 | 看到了却答错？ | 留痕和支持检查 | 提示词、模型 |
| 6 校验 | 答对了却被丢弃？ | 事件和日志 | 校验、结构 |

**真实工单：** B6b、B6d、B6e（一次只改一个变量）；证据题就是第 6 层的真实案例。

**考核：** 我准备 4 道错题，分别坏在不同层，不告诉你是哪层。你用证据定位，不许看代码改动记录。

### D. 上下文与记忆设计

**必须做到：** 能处理相关性、冲突、过期、来源权限和信息污染，并能解释为什么有些信息不该进提示词。

| 问题 | 真实例子 | 要能设计 |
|---|---|---|
| 相关性 | “那华北呢？”召回不到 | 用会话状态补查询 |
| 冲突 | 同一指标新旧结论不同 | 结构化主题和替换规则 |
| 过期 | 本月数字第二天还在用 | 业务有效期 vs 保留期 |
| 来源权限 | 用户降级后还用高权限结论 | 来源标签和读取时取交集 |
| 污染 | 文档写“请记住 X” | 写入来源限制 |

**真实工单：** C2、C4、C6、M2、M3、M5、M6。

**考核：** 给一组记忆和一次对话，你判断每条该不该用、为什么；再构造一个能让现有规则出错的新例子。

### E. 评测与实验分析（最优先）

**必须做到：** 能设计对照实验、隔离变量，识别小样本波动和题库泄漏，判断判分器本身有没有错。

| 技能 | 真实案例 |
|---|---|
| 看懂结果 | 冒烟 4 种类别和退出码 |
| 逐题比较 | 总数 33→33，但题目翻转 |
| 小样本 | “旧策略 4/4”后来变成 9 次错 1 次 |
| 隔离变量 | `passage_v1` 和 30/5 同时切换，失败后分不清原因 |
| 判分器错误 | “不低于”的“不”被当否定 |
| 题库泄漏 | 留出集被反复查看，已不算留出 |
| 费用决策 | 25 次重复值不值，需要多少次才够 |

**真实工单：** B5 的对照实验、B14b（你审题）、B15a～B15c、B6e。

**考核：** 给你一份没见过的前后结果，你写结论：能否上线、证据是什么、还差什么数据、下一个实验怎么设计。

### F. 可靠性与安全边界

**必须做到：** 给定崩溃或攻击发生的位置，能说出结果，并设计验证和恢复。

**崩溃位置分析（你要能自己填完这张表）：**

| 崩溃发生在 | 任务状态 | 可能的后果 | 怎么恢复 | 怎么验证 |
|---|---|---|---|---|
| 写任务和 Outbox 之间 | | | | |
| Outbox 已发布、Worker 未认领 | | | | |
| 模型已收费、结算未写 | | | | |
| 工具已执行、审计未写 | | | | |
| 检查点写入前 | | | | |
| 恢复提交后、投递前 | | | | |
| 发布后、记忆写入前 | | | | |

**安全边界：** 对每一道防线说清楚它防什么、谁在执行（模型 / 代码 / 数据库）、绕过后下一层是什么。

**真实工单：** B11（你写失败测试复现）、A11（数据源凭据）、A1、A4（RLS 为什么会弄坏恢复）、O5（故障演练）。

**考核：** 现场演练：我在测试环境注入故障，你按现象排查并恢复；再给你一个接口，你自己找出越权路径。

### G. 交付与团队沟通

**必须做到：** 能和业务、测试、运维协调，用证据说明收益、风险和后续选择。

| 对象 | 他们关心 | 你要能产出 |
|---|---|---|
| 业务 | 能解决什么、错了怎样、花多少钱 | 一页决策说明，不用术语 |
| 测试 | 怎么验收、边界在哪 | 验收标准和题集 |
| 运维 | 怎么部署、怎么回滚、半夜出事怎么办 | Runbook、告警说明 |
| 管理者 | 选 A 还是 B、风险和后续 | 两个选项和推荐 |

**真实材料：** 总计划第 14 节的 10 项决定，就由你逐项写决策说明。

**训练：** 我轮流扮演业务、测试、运维，提质疑。例如“准确率 90% 意味着什么？”“这个风险你愿意上线吗？”

**局限：** 我的模拟不能完全替代真人。**毕业前至少找一位真实的人（同事、朋友都可以）听你讲一次方案，并记录对方的反馈。**

### H. 独立实现

| 层级 | 要做到 |
|---|---|
| 1 | 能读懂调用链，能写单元测试断言 |
| 2 | 能写纯函数、规则、表驱动测试 |
| 3 | 能改已有模块，处理事务和错误 |
| 4 | 能写迁移、Worker 任务和端到端测试 |
| 5 | 能用 AI 辅助，但能判断 AI 写的代码对不对 |

**第 5 层很重要：** 真实工作里你会用 AI 写代码，你的价值在于判断它写得对不对、边界是否安全。

## 8. 毕业考核

**全部通过才算达到目标。** 不看资料、不给提示；可以用常规开发工具。

| 考核 | 内容 | 对应能力 |
|---|---|---|
| **盲修** | 我在测试环境注入 3 个未知故障（分属不同层），你定位、修复、写回归测试 | B、C、F、H |
| **实验** | 给一个改动提议，你设计实验、估算费用、运行、写结论 | E |
| **评审** | 我给一个有 5 处缺陷的设计（含安全问题），你找出并按严重程度排序 | A、D、F |
| **沟通** | 向真人讲一次方案并回答质疑；另交决策说明 | G |
| **独立项目** | 新领域的小型 Agent，从需求到交付由你完成 | 全部 |
| **延迟复查** | 过 2～4 周，用新场景再考每项能力 | 防止只是短期记忆 |

**独立项目要求（范围小，但要完整）：**

| 交付物 | 要求 |
|---|---|
| 需求和技术方案 | 哪些用模型，哪些用代码，并写明代价 |
| 代码 | 至少 1 个模型节点、1 个工具、结构化输出和校验 |
| 安全 | 租户或权限隔离，有对抗测试 |
| 可靠性 | 崩溃恢复或幂等，有故障演练 |
| 评测 | 题集 + 对照实验 + 结论 |
| 运维 | 启动、回滚和故障手册 |
| 汇报 | 一页决策说明 |

**我只在你提交后评审，不提前给方案。** 新领域由你选；没有想法时再提供 3 个选项。

## 9. 防止假进步

| 现象 | 处理 |
|---|---|
| 工单做完但变式题答不出 | 不算过关，不升级 |
| 有提示才答对 | 记录“有提示”，不算达到该等级 |
| 查了资料 | 没问题，但要说明；考核时不允许 |
| 只会解释，不会动手 | H 不过关，停在当前阶梯 |
| 同一概念错两次 | 换一种讲法或换真实例子，不重复原话 |
| 连续两次卡在同一工单 | 停下，回到前一层 |
| 我的判断和证据不符 | 以证据为准，并更正记录 |

**我也要被监督：** 如果我开始长篇讲解、重复读文档、偏离工单，你可以直接说“偏了”。

## 10. 费用和时间控制

| 项目 | 规则 |
|---|---|
| 单元测试、回放、假模型、本地检索 | 优先，免费或接近免费 |
| 付费运行 | 每次先说明要回答什么问题、多少次、大约多少钱，等你批准 |
| 付费重复次数 | 先判断几次才够区分，不用“多跑几次试试” |
