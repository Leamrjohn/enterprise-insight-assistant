## 2. 企业级标准（本计划的验收口径）

| 编号 | 标准 | 可检查的证据 |
|---|---|---|
| S1 | 租户隔离由代码和数据库双重保证 | 跨公司测试 0 泄漏；漏写公司条件时返回 0 行 |
| S2 | 模型只能提议，权限和发布由代码决定 | 对抗测试；任何模型输出都不能扩大范围 |
| S3 | 外部内容一律不可信 | 文档、历史、工具结果里的注入测试全部不生效 |

| S8 | 行为变更有门禁 | 提示词、模型、切分、路由变化都要过评测才能发布 |

**参考框架：** OWASP LLM Top 10、NIST AI RMF、OpenTelemetry GenAI 约定、MCP 规范。只作对照，实施前核对最新版。**本计划不等于通过 SOC 2、ISO 27001 等认证。**

**两级范围：**
- **本机级：可在本机验证。** 本计划必须做完，每项都有自动化或演练证据。
- **上线级：需要真实环境。** 如多机高可用、SSO 对接真实身份源、合规审计。先设计好接口，真实上线时再做，在此之前不能声称已具备。

## 3. 目标架构

继续使用**模块化单体**（一个代码库内分清模块边界，先不拆微服务）。原因：单人开发、并发还没测出瓶颈，拆分只会增加运维成本。

```text
接入层     API │ 身份 │ 限流配额 │ 准入
控制层     任务/Outbox │ 租约恢复 │ 主链编排 │ 策略快照
Agent 层   Planner │ Data │ Knowledge │ Reviewer │ 确定性校验
平台层     工具平台 │ 上下文引擎 │ 记忆平台 │ 模型网关 │ 提示词注册表 │ 配置与策略
数据层     平台库(RLS) │ 公司经营库(只读) │ 向量/全文 │ 对象存储 │ Redis
横切       遥测(trace/指标/日志) │ 审计 │ 评测门禁 │ 数据分级
```

**不变的约束：** 主链结构、经营库只读、SQL 校验、确定性发布、租约和检查点、记忆不当证据、文件上传冻结。

**依赖方向（用工具强制）：** 接入/控制 → Agent → 平台 → 数据。现在有两处反向：`core/gateway/*` 和 `core/middleware.py` 依赖 `modules`；`runtime` 和 `workflow` 互相依赖【代码】。

### 目标设计
一个工具只在一处声明，其他地方全部从登记表读取：

```python
ToolDefinition(
    name="sql_query", version="2.0.0", owner="data",
    model_description=..., input_model=..., output_model=...,
    side_effect="read",            # read / write，当前不开放 write
    required_permission="data:query",
    data_classification="business_internal",
    timeout_ms=10_000, retry=RetryPolicy(...), breaker=BreakerPolicy(...),
    idempotent=True, max_result_tokens=2_000, on_overflow="handle",
    fallback=None, rollout="enabled",
)
```

**统一执行流水线（顺序固定，任何工具不能跳过）：** 登记检查 → 策略快照 → 当前权限 → 参数校验 → 范围绑定 → 配额预占 → 熔断 → 超时和重试 → 执行 → 结果校验 → 脱敏和数据分级 → 大小控制 → 审计。**每次实际执行写一条记录**，用 `logical_call_id` 把重试串起来。

**错误分类：** `caller_error`（退回模型修正）、`denied`（立即停止）、`infra_error`（重试、熔断）、`exhausted`（结束任务）、`task_stop`（向上抛）。不再靠错误码集合推断，也不允许空错误码。

**Agent 循环 v2：**
- 每个 Agent 一份 `LoopPolicy`，模型只能看到分配给它的工具。
- 大结果放进任务作用域，模型只拿摘要和引用句柄，需要时再取。
- 只读工具可并行；循环消息接入上下文引擎；工具结果标记为不可信。
- 自主模式走“影子 → 单公司 → 默认”三步，每步过评测门禁。Planner 决定路线的外层不变。

**MCP：** 用适配器接入登记表。目录哈希固定，新增工具要审批，防止工具描述被投毒。远程传输和认证属于上线级。

**写操作工具：** 只预留审批接口（人工确认后执行），本计划不开放。

### 配置项
`TOOL_DEFAULT_TIMEOUT_MS=10000`、`TOOL_MAX_RESULT_TOKENS=2000`、`TOOL_BREAKER_THRESHOLD=5`、`TOOL_BREAKER_WINDOW_S=60`、`TOOL_BREAKER_COOLDOWN_S=30`、`TOOL_RETRY_MAX=1`。可按工具覆盖，按公司只能收紧。

### 目标分层
| 层 | 存什么 | 写入来源和门槛 | 作用域 | 生命周期 | 谁读 |
|---|---|---|---|---|---|
| 工作记忆 | 当前任务状态 | 工作流；已有检查点 | 任务 | 任务结束后按审计保留 | 主链节点 |
| 会话记忆 | 结构化状态：实体、时间、口径、约束、未决问题 | 代码抽取，模型提议要经校验 | 会话 | 随会话 | Planner、Reviewer |
| 情景记忆 | 过去任务的结论和来源 | 已发布报告（现有 `fact`） | 公司 + 用户 | 业务有效期和保留期 | Planner |
| 语义记忆 | 公司术语、指标口径、实体别名 | 管理员或审批后写入 | 公司 | 版本化，直到撤销 | Planner、Data、Knowledge |
| 偏好记忆 | 用户明确表达的偏好 | 用户明确表达或设置 | 用户 | 可随时删除 | Planner、报告 |
| 程序记忆 | 验证过的查询模式和分析套路 | 评测通过 + 人工审批，并去除具体数据 | 公司或全局 | 版本化 | Data、Planner |

**写入流水线：** 候选 → 分类 → 敏感信息检查 → 来源和权限标签 → 结构化主题（指标 + 对象 + 时间） → 冲突处理 → 审批（按层） → 存储和索引。

**读取流水线：** 硬过滤（租户、状态、有效期） → 当前权限与来源权限取交集 → 数据库限量召回（关键词 + 向量） → 重排 → 上下文预算 → 写选择清单。

**关键规则：**
- **记忆永远不当证据**，报告里的数字必须来自本次查询。
- 区分“业务有效期”和“数据保留期”；过期事实不能被召回。
- 权限收回后，来自高权限来源的记忆立刻不可用。
- 模型只能提议或标记，不能直接写入语义记忆或程序记忆。
- 防投毒：文档和历史里的“请记住……”不能直接成为记忆。
- 删除可级联：删用户、删公司、撤销来源文档时，相关记忆一起处理并留审计。

`MEMORY_PLANNER_MAX_TOKENS=1024`、`MEMORY_MAX_CANDIDATES=200`、`MEMORY_MIN_RELEVANCE=0.3`、`MEMORY_DEFAULT_TTL_DAYS=30`、`MEMORY_SOFT_DELETE_DAYS=90`、`MEMORY_VECTOR_ENABLED=false`。TTL 和启用的层可按公司设置，当前这些值都是代码常量。

### 目标设计
**每次模型调用都由 `ContextPack` 生成，不允许手工拼提示词：**

| 区段 | 信任级别 | 超预算时 | 位置 |
|---|---|---|---|
| 系统规则和提示词模板 | 可信 | 不可压缩 | 固定前缀（利于缓存） |
| 输出契约和工具说明 | 可信 | 不可压缩 | 固定前缀 |
| 当前问题和冻结范围 | 用户输入 / 可信 | 不可压缩 | 尾部 |
| 会话状态和长期约束 | 用户输入 | 不可压缩，超限时反问 | 中部 |
| 证据（查询结果、文档） | 不可信数据 | 按相关性压缩并标记 | 中部 |
| 历史消息 | 不可信数据 | 先压助手消息，再丢旧消息 | 中部 |
| 记忆 | 参考信息 | 按分数丢弃 | 中部 |

**规则：**
1. 每个节点一份版本化的 `ContextPolicy`：区段、顺序、预算、压缩器、超预算行为。
2. 超预算的处理顺序固定：压缩 → 丢弃可丢内容 → 反问或明确失败。**禁止静默发送。**
3. 每次调用把清单写入账本：策略版本、内容哈希、每段 token、压缩和丢弃原因。
4. 证据压缩保留含问题关键词、数字和实体的句子；数字不能被改写。
5. 分词器按模型配置，留安全余量，并用实际用量校准；镜像预置词表。
6. 不可信内容用固定定界符包裹，附带注入防护说明；真正的防线仍是代码。

`CONTEXT_ON_OVER_BUDGET=reject`（`reject/clarify`）、`CONTEXT_SAFETY_MARGIN=0.1`、`CONTEXT_COMPRESS_AT=0.8`、`CONTEXT_POLICY_VERSION`。节点预算初值：Planner 3000、Data 4000、Knowledge 4000、证据复核 4000、Reviewer 4000。要按真实分布校准，且不能超过任务总预算。

## 15. 风险和不做的事

| 风险 | 应对 |
|---|---|
| 平台改造让回答变差 | 每步先行为不变、后改行为；每步跑冒烟和相关评测 |
| 付费评测费用上升 | 优先回放；付费运行前报次数和费用级别，等批准 |
| 抽象过度 | 工具、记忆层要有实际消费者和评测收益，否则不启用 |
| 工单过大 | 单个工单不超过 10 个文件、400 行，超了就拆 |
| 用户不能验收 | 每阶段配合学习计划；用户能解释才算过关 |

**本计划不做：** 开放文件上传；接受用户原始 SQL；写操作工具；修改经营库数据；微服务化；为通过测试而改期望值。

**尚不清楚：** 真实用户的问题和文档长什么样、真实容量、供应商实际账单、11-03 方案中【记录】项的当前状态。F0 开工时先复核。
