# 工单 2.5.1：组件评测台只读调查（2026-11-01）

## 已有资产
- `backend/app/modules/evaluation/`：`business.py`/`observation.py`（端到端评测：经 API 跑任务，再从数据库读结果打分）、`result_fingerprint.py`（查询结果指纹）、`retrieval.py`（命中率、chunk 召回、chunk 精确率，仅有单元测试调用）、`thresholds.py`（阈值契约）。
- `backend/tests/fixtures/evaluation/`：42 个文件、80 条用例、56 个不重复问题；开发集 72、留出集 8。
  - 61 条有 `expected_route`（data_only 17、hybrid 18、knowledge_only 26）。
  - 80 条都有 `expected_result_fingerprint`；38 条有 `document_scope`（文档级范围）；**0 条有 chunk 级标注**。
- 语料：`data/business_knowledge_base/` 155 个文件，带 manifest（版本、seed）。
- 模型网关有 `local` 模拟实现；模型调用记录只存请求哈希、token、费用，**不存模型输出**，所以无法从历史冒烟回放。

## 四类组件评测的缺口

| 评测 | 可复用 | 缺口 | 是否花钱 |
|---|---|---|---|
| 检索（RAG） | `evaluate_retrieval`、本地嵌入与重排、38 条文档范围 | 无 chunk 级金标准；无 MRR、Recall@k；没有直接调用检索层的脚本 | 否（本地模型） |
| 报告校验 | `validate_report`、已发布报告 | 没有“篡改报告”用例集和拦截率统计 | 否（纯确定性） |
| Planner 路由 | 61 条带期望路线的用例 | 只能端到端跑；没有单独调用 Planner 的入口 | 是：约 60 次调用 |
| SQL 结果 | 80 条结果指纹字段（2.5.6 更正：多数只是场景名占位，真实校验值仅覆盖 9 个问题）、指纹计算函数 | 只能端到端跑；没有“固定计划 → Data Agent → 指纹比对”的入口 | 是：约 40～80 次调用 |
| 录制回放 | 网关已有统一入口和请求哈希 | 没有把模型输出录到本地文件、按哈希重放的网关 | 实现本身不花钱 |

## 拆分建议（按“先免费、后付费”）
1. 2.5.2 检索评测：从 `document_scope` 和文档用语生成 chunk 级候选标注（人工抽查），补 Recall@k、MRR，直接调用检索层出基线。
2. 2.5.3 报告校验评测：用已发布报告构造数字篡改、越权引用、无证据因果三类变体，要求拦截率 100%。
3. 2.5.4 录制回放网关：输出只写到本地 `evaluation-runs/`，不入库（输出含经营数据）；相同请求哈希直接重放。
4. 2.5.5 路由与 SQL 组件评测：录制一次需付费，预计 100～140 次调用、按历史单价约 $0.03～$0.06，**开跑前单独申请授权**；之后用回放离线重复跑。
