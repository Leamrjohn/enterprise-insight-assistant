## 2. 工具扩展

### 2.1 工具目录（20 个，分批接入）

工具不是越多越好：定义本身吃 token，工具越多模型选错率越高。先小批验证，测量后再决定要不要继续加。

| 域 | 工具 | 风险 | 批次 |
|---|---|---|---|
| 数据/指标 | `sql_query`、`template_query` | 只读 | 已有 |
| 数据/指标 | `metric_lookup`、`dimension_list`、`data_freshness` | 只读 | T11a |
| 文档 | `rag_search` | 只读 | 已有 |
| 文档 | `doc_read`、`doc_list` | 只读 | T11a |
| 文档 | `doc_version_diff` | 只读 | T11b |
| 记忆 | `memory_search` | 只读 | T11b |
| 平台 | `report_export` | 只读 | T11b |
| 平台 | `report_save`、`feedback_submit` | **写（低风险）** | T11c |
| 文档管理 | `doc_ingest`、`doc_update`、`doc_retire`、`doc_reindex` | **写（中/高风险）** | T11d |
| 记忆 | `memory_write`、`memory_forget` | **写（中/高风险）** | T11d |
| 数据修正 | `propose_data_fix` | **写（只写 staging）** | T14 |

**文档和记忆写工具的边界：**

- `doc_ingest` 只从平台已登记存储导入文件，不新增上传接口，上传入口仍冻结。
- `doc_retire`、`memory_forget` 一律软删除，撤销窗口内可恢复。
- `memory_write` 只提交候选，是否写入由代码按写入门槛和来源权限决定，模型不能绕过。
- 所有写工具的公司范围来自运行时上下文，不来自模型参数。

**待办，不在本轮范围：**

- `schedule_create`：会创建周期性副作用，等 T13 审批框架稳定后再评估。
- `schema_search`：与现有 `describe_table` 功能重复，删除。

### 2.2 加工具只改 4 处

T11a 的核心不是加工具，而是验证"加工具只改 4 处"这条承诺成立：登记、MCP 服务处理函数、结果转换、节点工具集配置。验收时加一个假工具，确认 `nodes/` 和 `analysis/` 零改动。

### 2.3 工具选择测量（条件工单）

20 个工具时先测，不预设要做检索。触发条件二选一：

- 单个节点可用工具超过 15 个；
- 工具选择准确率比全量列表下降 5 个百分点以上。

未触发就记录结论并关闭 T12；触发才实现检索（领域粗分 + 语义筛选）。

### 2.4 写操作边界

**写操作开放（2026-11-25 用户决定），但经营库永久只读，这条不变量不破。** 写操作只落在三个地方：

| 位置 | 例子 | 机制 |
|---|---|---|
| 平台资产 | 保存报告模板、提交反馈 | 用户确认 + 幂等 + 审计 |
| 知识库和记忆 | 从已登记存储导入文档、更新、下线、重建索引；提交记忆候选、遗忘 | 用户确认或管理员审批 + 软删除 + 撤销窗口；记忆写入过门槛 |
| 数据修正 | `propose_data_fix` 只写 staging 表 | 人工批准后由运维脚本落地，Agent 不直接改经营库 |

### 2.5 风险分级与审批

| 风险 | 例子 | 机制 |
|---|---|---|
| 低 | 保存报告、提交反馈 | 直接执行 + 审计 |
| 中 | 数据修正申请、导入或更新文档、提交记忆候选 | 用户确认 + 幂等键 + 审计 |
| 高 | 下线文档、遗忘记忆、重建索引、改公司策略（R9） | 管理员审批 + 软删除 + 撤销窗口 |

**每个写工具必须具备：** 幂等键、审批事件、执行审计、失败补偿、跨公司拒绝、超时后的状态查询。

### 2.6 验收

- 每个工具在登记表声明一次，有契约测试。
- 给节点加工具只改 4 处，`nodes/` 和 `analysis/` 零改动。
- 工具定义总 token 有测量值；节点只看到本节点工具集。
- 写工具重复提交只产生 1 次副作用；审批拒绝后 0 次执行；撤销窗口内可恢复。
- 工具选择准确率有基线，扩工具前先看数字。

## 3. 数据方案

### 3.1 三类数据，三种证据

| 用途 | 数据来源 | 为什么 |
|---|---|---|
| 对外可比 | 公共基准子集（2 个） | 自建题集的数字外人无法判断水平 |
| 业务覆盖 | 合成数据 + 人工审核 | 公共集没有本项目场景 |
| 真实说服力 | P1 试点的 30 条真实提问 | 唯一无法造假的证据 |

**不要只用合成集当唯一证据**，那等于自己出题自己考。

### 3.2 公共基准（只做 2 个）

| 模块 | 基准 | 说明 |
|---|---|---|
| SQL | BIRD mini-dev | 最贴近真实企业库；需要单独评测环境，见下 |
| RAG | CRUD-RAG（中文） | 中文语料，比英文 RAG 集贴场景 |

**BIRD 的额外要求：** 它要求跨库自由查询，与"所有查询限定在当前公司"冲突。必须搭独立评测环境：单独的数据源、单独的执行账号、只在这个环境里放开公司作用域，评测结果不回流主链。

**待办，暂不做：** BFCL（通用函数调用格式，和本项目关系不大）、τ-bench、LongMemEval、LoCoMo、C-MTEB。记忆模块本轮没有外部基准，报告里要如实写明这条差距。

**使用规则：**

1. 开工前查许可和可下载性，只取子集，记录版本和哈希。
2. 只跑测试 split，不拿测试集调参。
3. 报告里单独一行"外部参照"，不和自建题集混算。
4. 不设为 CI 硬门禁，先作为基线记录。
5. 注意污染：模型可能见过公开基准，结论只作参照。

### 3.3 合成数据规则

1. 先由人定 schema、口径和业务规则。这是可信度的来源。
2. **生成模型 ≠ 被测模型**。业务用 DeepSeek，就用另一个模型生成数据。
3. 生成**第二家公司**：不同的表名、单位、口径、行业术语。这是 R7"换一家公司不依赖演示定义"的验收基础。
4. 人工抽审至少 10%，重点看数字自洽和口径冲突。
5. 记录生成脚本、随机种子、模型版本；冻结后算哈希。
6. 留出 30% 不参与调参。
7. 每条数据标来源：`real` / `synthetic` / `public`。

### 3.4 脏数据清单

合成数据的通病是太干净。必须人为注入：

- 单位不一致（元/万元、百分比/小数）
- 过期制度和同名不同义的文档
- 互相冲突的两份制度
- 缺字段、空值、重复行
- 超长文档和表格密集文档
- 错别字、简繁混用、编码问题

这些是回答"鲁棒性"问题时的弹药。

### 3.5 验收

- 每类数据集有来源标注、版本、哈希和留出比例。
- 第二家公司换库后，不要求改代码即可跑通（允许配置改动）。
- 公开基准报告可复现：同版本、同子集、同脚本。
- 合成数据有人工审核记录。

## 4. 技术选型：主流与慎用

| 放心用 | 原因 |
|---|---|
| Postgres + pgvector、Redis、FastAPI、Alembic | 主流，面试官熟悉 |
| LiteLLM、MCP、OTel、Prometheus/Grafana | 当前企业常见组合 |
| Langfuse 或 Phoenix、RAGAS | LLM 观测和评测的常见工具 |
| Playwright、GitHub Actions、Docker Compose | 标准工程栈 |

| 慎用 | 原因 |
|---|---|
| Neo4j 做记忆 | 没有明确理由会被追问 |
| 自研向量库 | 负信号 |
| K8s 本地模拟 | 演示价值低、运维成本高 |
| 多代理框架堆叠（CrewAI/AutoGen） | 讲不清取舍就扣分 |
| LangChain 全家桶 | 面试官会问"为什么不用原生 SDK" |

慎用不是禁止。用之前先在 ADR 里写清"解决什么问题、替代方案是什么、复评条件"。

## 6. 落地顺序与依赖

## 8. 风险

| 风险 | 应对 |
|---|---|
| 工具越多选择越差 | T11a/T11b 小批验证；T12 测量后再扩 |
| 合成数据自产自销 | 生成模型和被测模型分离；人审；留出；标来源 |
| BIRD 与公司作用域冲突 | 独立评测环境，只读账号，结果不回流主链 |
| 公开基准英文偏差、许可不明 | 只做 BIRD 和 CRUD-RAG；开工前查许可；只作参照 |
| 基准污染 | 不拿测试集调参；结论只作参照 |
| 写操作引入越权面 | 范围限定；风险分级；审批；幂等；审计；跨公司测试 |
| 文档写入变相打开上传入口 | `doc_ingest` 只从已登记存储导入；不新增接口；测试证明没有上传路由 |
| 模型通过 `memory_write` 投毒记忆 | 工具只提交候选，写入门槛和来源权限由代码判断 |
| 工单变多拖长计划 | 固定插入顺序；T12 是条件工单；公开基准只做报告 |
| 为了显得高级堆技术 | 慎用清单；每个选型先写 ADR |
